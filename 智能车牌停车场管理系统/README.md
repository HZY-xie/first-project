# 基于 OpenCV 的智能车牌识别与停车场管理系统

## 项目说明
这是依据《企业项目实训》车牌识别与停车场管理系统开发任务书构建的 Python 桌面程序。`plate_recognition.py` 完整保留用户上传的 `test(2).py` 算法；`recognition_adapter.py` 将原算法包装成 GUI 接口。管理功能使用 PyQt5 + SQLite3 实现。

## 运行环境及步骤
推荐 Python 3.9–3.11（Windows）。

1. 解压 ZIP，打开项目文件夹，在终端运行 `python -m pip install -r requirements.txt`。
2. 项目已包含 `plate_template_24x48_done` 模板文件夹（31 个汉字、24 个字母、10 个数字），无需另外复制模板。
3. 在项目文件夹执行 `python main.py`。
4. 默认管理员账号 `admin`，初始密码 `admin123`。程序首次运行会创建 `parking.db` 和 50 个编号 A001–A050 的车位。
5. 识别图片时选择“打开图片识别”；接入 USB 摄像头可使用“启动摄像头”及“识别当前画面”。结果自动填入车牌输入框，必要时可以人工修正，再进行入场或结算。
6. 停车记录可按车牌、入场日期、在场状态筛选并导出 CSV。

> 注意：本项目现已包含原始字符模板和 5 张测试图片（位于模板文件夹内），能够进行基础识别流程测试。原算法主要针对普通蓝底七字符车牌，不保证适用于绿牌、新能源车牌或复杂环境。

## 功能模块
- 登录验证与角色权限（管理员可编辑或删除记录、维护黑名单与会员；操作员可办理进出场、查询和导出）
- 原 OpenCV HSV 蓝牌检测、字符二值化、投影切割与模板识别
- 图片识别 / 摄像头抓拍识别 + 人工纠错
- 入场自动分配空闲车位；重复在场、黑名单、满位拦截
- 出场按计费小时结算；小型车 2 元/小时、大型车 4 元/小时，不满一小时按一小时计
- 会员有效期和折扣系数；累计收费和在场状态统计
- 记录查询 / 管理员删除、修改未结算记录车型 / CSV 导出

## 代码结构
- `main.py`：PyQt5 登录界面及五个业务页面
- `database.py`：SQLite3 表结构、业务验证、进出场事务与费用计算
- `recognition_adapter.py`：原算法调用封装与图像接口
- `plate_recognition.py`：原上传识别后端，未修改算法
- `requirements.txt`：三方依赖
- `test_database.py`：数据库业务自动测试

## 数据库设计
- `users(id, username, password_hash, role)`：账户信息，密码使用 SHA-256 演示性哈希；生产场景请改为加盐密码哈希并提供改密功能。
- `spaces(id, code, occupied)`：车位状态。
- `records(id, plate, vehicle_type, space_code, entry_time, exit_time, duration_hours, fee, member_discount)`：停车业务明细。
- `blacklist(plate, reason, created_at)`：禁止入场车辆。
- `members(plate, valid_until, discount)`：会员有效期和费用系数。

车辆入场事务同时更新车位及新增记录；出场事务同时完成收费记录与车位释放。程序启动时自动从在场记录校准占用状态。

## 提交前检查
1. 模板已随项目提供；确认 `plate_template_24x48_done` 目录存在。
2. 放入合法可用的测试车牌图片，亲自检查每张的识别结果。
3. 运行 `python -m unittest -v test_database.py` 检查业务逻辑。
4. 现场运行 GUI，拍摄登录、识别、入场、出场、车位、查询截图，按学校要求插入提交说明文档。
5. 修改默认管理员口令（当前演示版未实现界面修改，提交/部署前应增加改密功能），避免公开真实车辆数据。

## 已知限制
- Python 文件和样例测试无法替代实际摄像头/图片测试；需要在有图形桌面的 Windows 环境进行真实 GUI 验证。
- 系统的数据库设计为本地单机操作，不适合同时多终端并发修改。
- 为保持原算法，车牌识别仅对符合普通蓝牌格式的 7 字符结果自动接受；识别结果可能出错，办理业务前应人工确认。
